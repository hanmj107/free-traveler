## 참고

- 이 화면은 `TASKS/WAVE_PLAN.md`의 정식 순서(W06/W07 Component → W08 Page
  Owner)보다 훨씬 뒤에 구현되었다 — 다른 4개 화면(SCR-002~005)을 먼저 완료한
  뒤 사용자 요청에 따라 마지막으로 구현했다. `TASKS/WAVE_STATE.json`에는 실제
  Task ID 기준으로 진행 상태가 반영되어 있다.
- 이 작업 과정에서 이 화면과 무관한 실제 버그 2건을 함께 고쳤다: (1)
  `GET /api/mates`가 `created_at`을 반환하지 않아 "최근 동행글" 정렬이 불가능해
  API-MATE-POSTS의 기존 파일에 필드를 추가했다. (2) 기존 `tests/e2e/public-smoke.spec.ts`의
  E2E-001 테스트가 "대표 소개" 링크를 화면 전체에서 찾아 Header·Footer 링크와
  충돌했다 — `<main>` 범위로 좁혀 수정했다.
- 국가별 안전정보(`src/data/countrySafety.ts`)의 `lastVerifiedAt`은
  2026-09-01로 고정된 정적 데이터라, 오늘 날짜 기준으로는 항상 "7일 경과"
  경고가 뜬다 — 이는 버그가 아니라 설계된 동작이다(정적 데이터의 특성상
  실제 운영 중에는 주기적으로 `lastVerifiedAt`을 갱신해야 경고가 사라진다).
- Playwright E2E 전체(`public-smoke`·`travel-tools`·`mate-auth`, 12개)를
  실제 Supabase 프로젝트에 대해 실행해 전부 통과를 확인했다(1 worker 기준;
  4 worker 병렬 실행에서는 로컬 환경 메모리 제약으로 간헐적 timeout이
  발생해 CI에서도 필요시 동시성 조정을 고려해야 한다).
