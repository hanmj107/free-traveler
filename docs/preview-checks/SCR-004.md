## 확인해야 할 항목

1. Section 순서: Header → Intro(CTA Banner) → Filter+결과 요약 → 동행 목록(최대
   8개)+상세(Desktop 좌우 분할) → 참가 방법 3단계+안전 안내 → Footer
2. Filter: 국가/지역/기간/스타일/모집 상태를 바꾸면 목록과 "조건에 맞는 모집글 N건"
   문구가 즉시 반영되는지, "필터 초기화"가 실제로 초기 상태로 되돌리는지
3. 목록 0건일 때 완성형 Empty State(조건 초기화+작성 CTA)가 보이는지, 큰 빈 영역이
   없는지
4. 카드 선택 시 같은 화면에서 상세가 열리는지(Desktop: 우측 고정, Mobile: 전체화면
   Drawer + 닫기 버튼)
5. 상세에서 소개(본문)·모집 상태·참가 요청 버튼이 보이는지
6. 비로그인 상태에서 참가 요청/신고/차단 버튼이 각각 `/account`로 유도하는지
7. 로그인 계정으로 참가 요청 시 메시지 입력 → 제출 → 같은 글에 다시 요청 시 "이미
   참가 요청을 보낸 모집글입니다." 안내가 뜨는지
8. 본인이 작성한 글의 상세에서는 참가 요청 버튼 대신 관리 안내 문구만 보이는지
9. 신고 Dialog 제출 시 접수번호가 화면에 표시되는지, 차단 버튼 클릭 시 완료 안내가
   보이는지
10. Mobile 뷰에서 Filter·목록·상세·CTA 버튼 순서와 위치가 자연스러운지

## 참고

- 이 화면은 `TASKS/WAVE_PLAN.md`의 정식 순서(W13/W14 Component → W15 Page
  Owner)보다 앞서 사용자 요청에 따라 구현되었다 — `TASKS/WAVE_STATE.json`에는
  실제 Task ID 기준으로 진행 상태가 반영되어 있다.
- `GET /api/mates`는 원래 모집중 글만 반환하도록 구현했었으나, 이번 SCR-004
  Filter의 "모집 상태" 옵션(마감 글도 함께 볼 수 있어야 함)을 지원하기 위해 모든
  글을 반환하고 모집중/마감 좁히기는 클라이언트에서 하도록 수정했다.
- "모집 인원" 필드는 표시하지 않는다. `mate_posts` 스키마에 정원 컬럼이 없다
  (docs/02_SRS_BASELINE.md 2026-09-03 결정 — SCR-003 동행 작성 Form과 동일한 이유).
- 실제 Supabase 인증 상태를 포함한 전체 흐름(로그인 → 참가 요청 → 승인/거절)은
  마이그레이션이 아직 반영되지 않아 로컬에서 실제 DB로 확인하지 못했다. 참가
  요청/신고/차단/승인·거절 API는 Mock 기반 Unit Test로만 검증했고, 실제 Supabase
  연결 후 다시 확인한다.
