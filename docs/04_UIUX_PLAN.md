# Free Traveler — UI/UX Plan v1.0

- **문서 ID:** UIUX-TRAVEL-001
- **작성일:** 2026-09-10
- **참고 문서:** `docs/01_PRD.md`, `docs/02_SRS_BASELINE.md`, `docs/PROJECT_SCOPE.md`, `docs/03_UI_COVERAGE_ANALYSIS.md`
- **디자인 참고:** `design-reference/vendor/airbnb/DESIGN-airbnb.md` — 레이아웃 밀도, 단일 포인트 컬러 운용, 카드 중심 그리드, 단일 shadow tier, 라운드 코너 형태 언어 등 **구조적 원칙만** 참고한다. Airbnb의 색상(Rausch #ff385c), 서체(Cereal), 워드마크, 3-product 내비게이션, "Guest favorite" 배지 등 **상표·브랜드 요소는 사용하지 않는다.**

## 1. 브랜드 원칙

| 항목 | 내용 |
|---|---|
| 브랜드명 | Free Traveler |
| 톤 | 흰 배경 위에 짙은 회색 텍스트를 기본으로 하고, 코랄 포인트 컬러를 CTA·강조 요소에만 절제해서 사용한다(Airbnb의 "90%는 흰색+잉크, 한두 곳만 포인트 컬러" 운용 원칙을 구조적으로 차용) |
| 형태 언어 | 부드러운 라운드 코너(카드 12~20px, 버튼 8~10px, 검색바·칩은 pill) — 각진 요소는 그리드 자체에만 남긴다 |
| 사진 활용 | 여행지·대표 소개는 사진이 시각적 무게를 담당하고, 타이포그래피는 절제한다 |
| 상표 회피 | Airbnb 고유 요소(정확한 색상값, 서체, 워드마크 형태, "NEW"/"Guest favorite" 배지류 문구·형태)는 재현하지 않는다 |

### 2-5. 접근성·터치 규칙

- 모든 인터랙티브 요소의 터치 영역은 **최소 44×44px**을 확보한다(SRS의 WCAG AA 최소 기준 24×24px, REQ-NFR-ACC-006 보다 상향한 자체 기준).
- 모든 포커스 가능한 요소는 2px 코랄 또는 잉크 색 아웃라인의 키보드 포커스 링을 갖는다(`outline: 2px solid var(--color-coral); outline-offset: 2px`).
- 색상만으로 상태를 구분하지 않고 아이콘·텍스트 라벨을 병기한다(REQ-NFR-ACC-004).
- 의미 있는 이미지는 실제 장소·상황을 설명하는 대체텍스트를 사용한다(예: `alt="교토 후시미 이나리 신사의 붉은 도리이 길"`), 장식용 이미지만 `alt=""`.

## 4. Section 배치 공통 규칙

- 모든 화면은 Header와 Footer 사이에 목적이 분명한 Section을 순서대로 배치하며, 각 Section은 **제목 + 1~3문장 설명 + 실제 콘텐츠 또는 명확한 CTA**로 구성한다.
- Desktop 콘텐츠 최대 폭 1200~1280px(중앙 정렬), Section 상하 여백 64~96px. Mobile은 Section 상하 여백 40~64px, Card는 1열.
- Hero는 1440px 뷰포트 기준 화면 전체 높이를 차지하지 않는다(약 560~600px, 뷰포트 높이 900px 기준으로 다음 Section 상단 120~150px가 미리 보이도록 구성).
- **패턴 팔레트**(Hero / Card Grid / 좌우 분할 / Chip 목록 / 3단계 안내 / CTA Banner)를 화면별로 교차 사용해 같은 형태의 Card만 반복하지 않는다. 각 화면의 패턴 배정은 §5~§9에 명시한다.
- Lorem ipsum, "준비 중", "정보 확인 필요" 같은 placeholder 문구, 의미 없는 빈 Card, 과도한 빈 여백을 두지 않는다.
- 서버/DB 데이터가 없는 상태(Empty)에도 **① 상황 설명 ② 이용 방법 ③ 다음 행동 CTA**를 함께 표시해 빈 화면처럼 보이지 않게 한다.
- 모든 제목·설명은 완성된 한국어 문장으로 작성한다. 아래 각 Section에는 실제로 사용할 수 있는 예시 카피를 제시한다(최종 카피는 콘텐츠 확정 단계에서 다듬을 수 있으나 placeholder가 아닌 완성 문장 형태를 유지한다).

## 11. 요구사항 반영 확인
